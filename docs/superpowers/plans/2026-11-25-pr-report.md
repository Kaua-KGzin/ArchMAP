# PR Report Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the architecture delta of a pull request (health, new/resolved findings, new bottlenecks, lost test coverage) as one sticky PR comment, built on `archmap diff --snapshot-a/--snapshot-b`.

**Architecture:** Fix snapshot loading, export findings with a stable `key`, extend `diff_reports` with a findings/test/bottleneck delta, render it as Markdown from a pure function, and add an opt-in `comment` input to `action.yml` that analyzes the base via `git worktree` and upserts one comment with `gh api`.

**Tech Stack:** Python ≥ 3.11 stdlib only, pytest, ruff, mypy; bash + `gh` in a composite GitHub Action.

**Spec:** `docs/superpowers/specs/2026-11-25-pr-report-design.md`

## Global Constraints

- No new runtime dependencies (`dependencies = []` stays empty).
- Coverage gate `--cov-fail-under=85`; `ruff check .` and `mypy src/archmap/ --ignore-missing-imports --exclude "web-ui"` must pass.
- Existing keys of `diff_reports` output and of the exported JSON do not change; new fields are additive.
- Marker string, exactly: `<!-- archmap:pr-report -->`.
- At most 15 rows per list, then `…and N more`; whole body ≤ 60,000 characters (GitHub limit 65,536).
- Empty delta renders exactly: `No architecture changes detected.` (after the marker and heading).
- Comment and CLI output in English.
- The Action's report step never fails the job; posting errors become `::warning::`.
- No `pull_request_target`. Inputs reach scripts via `env`, never `${{ }}` inside `run:`.
- Commits end with `Claude-Session: https://claude.ai/code/session_01FQ5hfrtjNTkNozpRqKHw3Y`.

## Review Focus

1. **Head analysis failed a gate** (`min-health`, `fail-on-*` → step exit ≠ 0): the report step must still run (`if: ${{ !cancelled() && ... }}`) and post. Checked in Task 7, Step 3.
2. **`format: mermaid`** (no head JSON written): the report step analyzes the head itself. Task 7, Step 3.
3. **Base report from ArchMAP ≤ 1.5.0** (no `findings`, no `testedBy`, no `testMapping`): no crash, sections omitted, Markdown says so. Task 4 test `test_diff_without_findings_is_not_comparable` and Task 5 test `test_render_marks_incomparable_base`.
4. **Huge PR** (hundreds of new findings): lists truncated at 15, body under 60,000 chars. Task 5 test `test_render_caps_rows_and_size`.
5. **Snapshot written by `analyze --format both`** (the exact file users have): round trip must not crash. Task 1 test `test_snapshot_round_trip_on_sample_project`.
